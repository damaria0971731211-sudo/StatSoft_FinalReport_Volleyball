## 階段 1：定義題目（Define）

**在做什麼**
把「政大體育館晚餐場、消夜場排球野場的人員安排」這個生活問題，變成老師要的「以統計為核心、可檢驗的問題」。

**完成了什麼**
- 起點是我的構想：報名、程度分級、分隊，加上攻擊成功率、搭檔、位置等統計。
- AI 提醒「報名＋分隊」單獨會被看成只有表單，建議讓統計當主角。
- 我把題目擴大成**全台球館通用平台**：一份個人檔案跨館累積數據，用統計估出真實程度，報名時可以依程度設限制。核心痛點是「自報程度不準」。
- 我覺得第一版「跟統計的關聯顯現不出來」，AI 補了「平台功能對應統計問題」的對照，再收斂成**1 個主問題**：跨館評分是否比自報程度更準地分級，並讓分隊更均衡。
- 事先鎖定成功門檻（15:16 確認）：Spearman 至少提高 0.05、平均分差至少降 0.2 分，用新種子重跑 1,000 次判定。
- 路線定為「生活與研究工具路線（含模擬）」。攻擊成功率、位置改成選做，用職業資料示範。

**下一步**
- 提案定稿後不再改主問題與門檻，避免「先看結果再挑指標」。
- ✍️ 我為什麼接受這個主問題：＿＿

## 階段 2：資料策略（Plan／Review）

**在做什麼**
決定要用哪些資料，並符合指引「至少 3 份資料、2 個獨立來源」。

**完成了什麼**
- AI 原本建議我去野場記錄比分，**我拒絕了**，因為沒辦法到現場收集。改成公開資料加模擬資料。
- 我自己定義兩類資料的分工：**公開資料是證據，模擬資料是示範**，網頁與影片會標明哪些是模擬。
- 選定資料：D1 datavolley 範例檔（MIT）、D2 德甲 volleystat（CC0）、D3 模擬資料。原本的 NCAA 因為條款禁止抓取與公開散布，**我決定不用**；Kaggle VNL 我手動下載，12/03 前沒用到就刪掉。
- 模擬資料：4 個球館、150 人、8 週，參數借自 D1。

**下一步**
- 等老師回覆能否用模擬加公開資料（14:31 已詢問）。
- 在自己電腦完成 VNL 下載與授權確認，或決定刪掉。

## 階段 3：統計模型與程式（Code）

**在做什麼**
R 和 Python 各做實質任務，回答主問題和支持分析。

**完成了什麼**

| 模組 | 語言 | 做什麼 | 主要結果 |
|---|---|---|---|
| 模擬資料產生器 | Python | 產生已知真實實力的球員和比賽 | 772 局，有真值可以驗證 |
| 實力評分模型 | R | 用比分估每個人的實力，自報程度當先驗，加入球館效果 | 德甲資料樣本外命中 69%；模擬資料排名相關 0.82 到 0.88 |
| 自報程度偏誤 | R | 檢定大家是不是系統性高估自己 | 找到並修正 5 個問題（見階段 5） |
| 分隊原型 | Python | 隨機、自報蛇形、評分最佳化三種分隊比較 | 平均分差 5.53、5.05、4.83；評分最佳化比蛇形少 0.22 分 |
| 報名門檻 | Python | 把「誤放、誤擋」當成型一、型二錯誤，用 ROC 選門檻 | 自報 4 級以上的人有 33% 其實未達標 |
| 分隊實驗設計 | Python | 真實要驗證需要幾晚 | 比自報蛇形需每組約 512 晚，跨 20 館約 6 到 7 週 |
| AI skill：balance-teams | Python | 檢查名單、平衡分隊、和隨機分隊比較 | 跑 5 次，含 2 個邊界案例 |

**下一步**
- 用鎖定的新種子做確認性重跑，判定主問題。
- R 套件在我電腦重跑並產生 renv.lock（進行中）。
- ✍️ 哪個結果最出乎我的意料：＿＿
