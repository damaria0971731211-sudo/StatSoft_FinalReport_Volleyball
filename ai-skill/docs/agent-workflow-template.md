# AI agent 協作流程紀錄（範本＋本專題第一條流程）

依課程指引第 06 節：Define → Plan → Review → Code → Test → Reflect。每一階段都要標出**人工決策點**與**產出證據**。只貼對話截圖不算證據。

使用方式：每做一個功能（例如 R 實力模型、Python 分隊、網站），複製一份「空白範本」填寫。下方附一份已部分填好的例子（balance-teams 技能），標 ＿＿ 的地方是 Iris 必須自己寫的，AI 不能代填。

## 例子：balance-teams 技能（2026-11-26）

### 基本資料

| 欄位 | 內容 |
|---|---|
| 流程名稱 | 野場排球平衡分隊技能 |
| 日期 | 2026-11-26 |
| 工具／模型 | Claude Code 雲端工作階段（Anthropic Claude Opus 5.5），Iris 的 claude.ai 帳號；未呼叫外部付費 API |
| 操作者／審查者 | AI agent 撰寫與執行；Iris 審查（＿＿ 待填日期） |
| 對應檔案 | `skills/balance-teams/`、`docs/skill-run-log.md` |

### 1. Define

- Iris 原始想法（2026-11-26 原文）：「想要解決的是政大體育館排球 晚餐跟消夜場的人員安排問題…做一個野場排球報名系統 可以有程度分級 然後分隊…」
- Iris 的限制：一人一組；沒有真實野場紀錄，只用網路公開資料與模擬隨機數據。
- 需求與成功指標（AI 草擬，待 Iris 確認）：
  1. 名單有錯時一定停止並逐列回報。
  2. 分隊後各隊人數最多差 1。
  3. 各隊平均實力全距小於 2000 次隨機分隊的第 5 百分位。
  4. 小名單結果與窮舉最佳解相同。
- Iris 補充或修改：＿＿

### 2. Plan

```
模擬報名名單 (CSV) ──► balance_teams.py ──► teams.csv ──► 網站 / Python 原型
       ▲                     │
R 模型 rating 欄位 ──────────┘──► report.md / report.json ──► 執行紀錄、報告
```

- AI：寫 SKILL.md、腳本、三份測試名單，依 SKILL.md 跑測試並記錄。
- Iris：審查需求與演算法、確認測試判定、決定是否接受 D01 修正、把技能放進 repo。
- 依賴：rating 欄位之後由 R 模型產生（另一條工作線）。

### 3. Review（人工決策點，待 Iris 填）

| AI 提議 | Iris 的決定 | 理由 |
|---|---|---|
| 技能題目選「分隊＋檢查」，而不是「資料格式檢查」 | ＿＿ | ＿＿ |
| 實力 = rating，沒有時用 level×2 | ＿＿ | ＿＿ |
| 目標函數：平均實力全距＋0.5×沒有舉球員的隊數 | ＿＿ | ＿＿ |
| 每隊 4 到 6 人，超出就停止而不是自動排候補 | ＿＿ | ＿＿ |
| 基準方法用隨機分隊 | ＿＿ | ＿＿ |

### 4. Code

- 我自己的反思：＿＿
