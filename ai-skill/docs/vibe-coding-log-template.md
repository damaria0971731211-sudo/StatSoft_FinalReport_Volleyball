# Vibe Coding 迭代紀錄（範本）

依課程指引：至少一次以自然語言迭代原型，保留**需求、生成版本、人工修改、測試前後差異**。

建議做法：選一個看得到的小原型（例如網站上的「報名→分隊」頁面，或 Python 分隊原型的介面），用自然語言請 AI 生成，再一輪一輪修改。每一輪都存一個版本（git commit 或檔名加 v1、v2），並在下表記一筆。至少 3 輪比較能看出變化。

> 注意：這份紀錄要寫 Iris 自己說了什麼、自己改了什麼。AI 不能代填「人工修改」與「我的判斷」兩欄，也不能杜撰沒有發生的錯誤。

## 迭代紀錄

| 輪次 | 日期 | 我對 AI 說的話（原文） | AI 生成了什麼（版本／commit） | 我看到的問題 | 我自己的修改（不是 AI 改的） | 測試：修改前 → 修改後 |
|---|---|---|---|---|---|---|
| 1 | | | v1 | | | |
| 2 | | | v2 | | | |
| 3 | | | v3 | | | |

填寫提示：

- 「我對 AI 說的話」貼原文，不要事後美化。
- 「我看到的問題」寫具體現象，例如「貼上 26 人分 7 隊時沒有報錯，直接分出 3 人一隊」。
- 「測試：修改前 → 修改後」寫同一個輸入的前後結果，例如「26 人 7 隊：修改前分出 3 人隊 → 修改後顯示『人數不夠，建議 6 隊』」。可直接用 `skills/balance-teams/examples/` 的名單當固定輸入。

## 比較與反思

- 自然語言描述在哪裡不夠精確，導致 AI 做錯？
- 哪一次我拒絕或大改了 AI 的產出？為什麼？
- 如果不用 AI，哪些部分我能自己完成？
